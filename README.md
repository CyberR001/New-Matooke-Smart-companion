 MatookeSmart Companion

A farming intelligence, early-order marketplace and value-addition platform for Uganda's matooke value chain.
Farmers decide when and how to sell, buyers reserve future supply with deposits, and the MatookeSmart Hub turns surplus into products.

## The problem
Matooke farmers sell blind. They do not know when prices will fall, they have no dependable buyer before harvest, and urgent cash needs push them into expensive loans or distress sales. Surplus rots, disease is noticed late and support programmes go unseen. Buyers face irregular supply.

## How the company makes money
| Stream | How it earns |
|---|---|
| Order fees | 4% of the value of every settled order |
| Subscriptions | Smart Farmer (UGX 5,000), Professional Farmer (UGX 15,000), Buyer / Institution (UGX 50,000), monthly |
| Hub margin | Profit on flour, chips, crisps and peeled matooke made from purchased surplus |

The **Insights** page (administrator account) reports all three streams from the database.

## Features
- **Accounts and roles:** farmer, buyer, hub and administrator, with PIN sign-in and registration.
- **Price forecasting:** weekly price series per market; seasonal index, trend regression and an 80% range for the next eight weeks, with a confidence rating.
- **Selling plan:** compares selling fresh, an early order and offering surplus to the Hub, then splits the harvest across routes using expected value after fees and risk.
- **Farm Doctor:** weighted symptom rules for seven banana conditions, confidence scores, a follow-up question, and referral to an extension officer for low-confidence or notifiable diseases.
- **Marketplace and matching:** farmers list harvests, buyers post requirements, and a scoring model (location, price, timing, quantity) ranks matches.
- **Order lifecycle with ledger:** agreed, deposit paid, delivered, settled, plus dispute and cancel. Deposits, final payments and fees are written to a ledger.
- **Hub:** buying notices, farmer offers with accept and reject, product economics, and batch yield and margin records.
- **Opportunities and plans:** programmes filtered by district, and membership plans.
- **Insights:** farmers, buyers, order value, fees, subscriptions, Hub margin, order status and plan mix.

## Run locally
```bash
pip install -r backend/requirements.txt
cd backend
uvicorn main:app --reload
```
Open http://127.0.0.1:8000. The database is created and seeded on first start. Reset it any time with `python seed.py`.

## Deploy
Push this repository to GitHub and create a Web Service on Render (or any host that runs Python). `render.yaml` is included.

## Project structure
```
backend/
  main.py      API, authentication, order and ledger logic
  engine.py    forecasting, advice, disease rules, matching, product economics
  seed.py      schema and seeded dataset (users, 2 years of weekly prices, listings, requirements, orders, batches)
frontend/      static single-page app served by the API
```

## Data and methods
Seed data is generated by `backend/seed.py`: 86 users, 832 weekly price records across eight markets, 95 listings, 60 requirements, 42 orders with ledger entries, 16 Hub batches and 12 opportunities.
The disease module is a rule-based decision aid; photo analysis is not implemented. Payments are recorded in the ledger and are not connected to a mobile money provider.
